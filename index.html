让长期运行的 AI 助手
从「会聊天」到「靠得住」

三个套件的共同出发点是一个很具体的观察：demo 里表现很好的助手，一旦开始长期干活就开始走样。 称呼会变，语气会平，三天前答应过的事会丢，加第五个工具时主程序已经没人敢碰。 这里的三套东西，各补一段路。全部 MIT，零依赖或近零依赖，Node.js 20+。

三个仓库

dsh-agent-craft

智能体养成

五个独立组件，各补一个缺口：人设锚点周期注入、六件记忆工具、文风卡尺、可视化卡尺、QQ 桥接方法。合起来覆盖一条完整链路 —— 记得住、说得像人、讲得清、接得出去。

52 files · MIT · anchor / memory / style / visual / bridge

dsh-capability-forge

能力锻造

把「加能力」和「改程序」拆开：一个 .mjs 文件就是一个工具，自动发现，不动主程序。再把「缺什么能力」变成一条走完的流水线 —— 登记、起草、测试、转正，测试不过不放行。

35 files · MIT · providers / gaps / dcc bridge

dsh-runtime-probe

运行时探针

采一帧本机状态，挂成 HTTP + SSE，配一张朴素面板。它不试图当监控系统 —— 只看历史趋势、告警规则、多机聚合那类活，有专门的东西。这个只回答一个问题：现在什么情况。

9 files · MIT · zero-dependency · /api/frame · /stream

几条不肯让的设计

事实层只升温不降温 一条事实不该因为很久没人提起就搜不到。体验层会凉，事实层永不发灰。
测试不过不放行 没测过的能力被转正，比没有这个能力更坏 —— 它会被当成可用的东西去调用。
锚点放在上下文末尾 模型对临近生成位置的内容权重更高。塞在开头等于让它跟几万字历史一起被稀释。
CPU 必须差两次 os.cpus() 给的是开机至今的累计值，直接算出来是平均值，不是此刻。
